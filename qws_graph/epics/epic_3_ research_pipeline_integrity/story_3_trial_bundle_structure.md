# Story — Trial Bundle: Co-located Artifacts per Run

## Status
draft

## Priority
P3 — Organization. Currently only CSVs are ingested to the graph; HTML reports and any
supporting markdown are generated to a flat directory and silently orphaned. Artifact
co-location becomes important once there are multiple trial variants producing overlapping
filenames in the same directory, or when an operator needs to reconstruct which HTML report
corresponds to which graph Run node.

## Summary
Define a standard per-run output directory structure so all artifacts produced by a trial
(CSV, HTML, supporting markdown) are co-located and traceable. Add a `qw record --bundle
<dir>` flag that auto-detects and ingests all recognized artifacts from a bundle directory
in the correct order.

## Problem
The liquidity sweep trial currently writes all output to a flat directory
(`research/trials/futures/liquidity_sweep/`):

```
baseline_results.csv
index.html
golden_results.csv
golden.html
position_sizing_results.csv
position_sizing_equity_curves.csv
position_sizing_summary.json
position_sizing.html
```

**What is actually ingested to the graph**: only the CSVs. The shell runner calls
`qw record --file baseline_results.csv --kind baseline_csv`. The HTML files are
written but never passed to `qw record` — they are already orphaned, not at risk
of orphaning.

**What this creates**:
1. No linkage between a `Run` node in the graph and the HTML report for that run. An
   operator querying `qw query --name run_history` cannot navigate to the visual report.
2. Filename collisions as new trials are added. A second trial writing `index.html` or
   `results.csv` to the same directory overwrites the previous run's artifacts silently.
3. No way to reproduce "which config produced which report" without cross-referencing
   timestamps or manually reading file contents.

**Note on `run_id`**: The `run_id` is generated deterministically by `parsers.py` from a
hash of the CSV content and provenance metadata — it is not known until after the file is
parsed. Output directories therefore cannot be named `{run_id}/` at write time. The
bundle structure must use a pre-run identifier (e.g., trial name + timestamp, or
`strategy_id` + datestamp).

## Goal
- Each trial run writes artifacts to a named subdirectory:
  `research/trials/futures/liquidity_sweep/runs/{YYYYMMDD-HHMMSS}/`
- The CSV, HTML, and any supporting files for that run live together in that directory.
- `qw record --bundle <dir>` detects the CSV (required), ingests it, and records the
  HTML path as a `BlobArtifact` or as a property on the `Run` node.
- A completed bundle directory is self-contained: given only the directory, an operator can
  reconstruct the full run.

- `research/run_liquidity_sweep_golden.sh`
- `research/run_liquidity_sweep_position_sizing.sh`

## Proposed Design

### Bundle Directory Layout
```
research/trials/futures/liquidity_sweep/runs/
  20260405-143022/          ← timestamp assigned at script start
    baseline_results.csv    ← graph-ingestable CSV (required)
    report.html             ← visual report (optional, linked)
    bundle.json             ← bundle manifest (generated by trial script)
```

The timestamp is assigned once at the top of the shell runner (`RUN_TS=$(date +%Y%m%d-%H%M%S)`)
and passed as an env variable or argument to the Python trial script. The trial script writes
all outputs to `runs/${RUN_TS}/`.

### Bundle Manifest (`bundle.json`)
A small JSON file written by the trial script at exit:
```json
{
  "trial": "liquidity_sweep_baseline",
  "run_ts": "20260405-143022",
  "strategy_id": "...",
  "files": {
    "csv": "baseline_results.csv",
    "html": "report.html"
  }
}
```
This enables `qw record --bundle <dir>` to locate files without guessing.

### CLI: `qw record --bundle <dir>`
Add a `--bundle` flag to the `record` subcommand:
- Reads `bundle.json` from the directory.
- Ingests the CSV file first (required; must succeed before HTML is recorded).
- If HTML is present, records it as a `BlobArtifact` with `artifact_kind = "report_html"`.
  This requires adding `"report_html"` to the `BlobArtifact.artifact_kind` literal in
  `models.py` (currently only `"tracker_md"` is supported).
- Returns a receipt with the `run_id` (generated post-parse) and all artifact paths.

### Model Change Required
`BlobArtifact.artifact_kind` in `models.py` is currently:
```python
artifact_kind: Literal["tracker_md"]
```
Needs to become:
```python
artifact_kind: Literal["tracker_md", "report_html"]
```
This is a schema change — update `BLOB_INGEST_QUERY` in `cypher.py` accordingly.

## In Scope
- Shell runners: assign `RUN_TS` at start; pass to trial scripts; write artifacts to
  `runs/${RUN_TS}/`.
- Trial scripts: accept output directory as argument (or env var); write all outputs there.
- `bundle.json` manifest written by trial script at completion.
- `qw record --bundle <dir>` CLI flag in `cli.py`.
- `BlobArtifact.artifact_kind` extended to include `"report_html"`.
- The new output paths linked in shell runner completion output.

## Out of Scope
- Ingesting the `position_sizing_equity_curves.csv` or `position_sizing_summary.json` as
  separate graph artifacts (these are intermediate files, not primary results).
- Versioning or retention policy for old `runs/` directories.
- Automatic cleanup or rotation of the flat output directory.

## Implementation Notes
- The `run_id` is content-addressed (hash of CSV + provenance) — it cannot be the bundle
  directory name. Use `run_ts` (write time) as the directory name instead. The `run_id`
  appears in the ingest receipt and can be written back to `bundle.json` after the CSV
  is ingested.
- Trial scripts currently have hardcoded output paths. Parameterizing via `--output-dir`
  CLI arg is cleaner than env var injection — the shell runner passes it explicitly.
- The `--bundle` flag and the existing `--file` flag should be mutually exclusive in the
  `record` subcommand's argparse config.
- HTML files can be large. Do not store raw HTML content in the Neo4j graph — store only
  the `artifact_path` (relative or absolute) as a `BlobArtifact` property. Raw storage
  belongs in the filesystem; the graph holds the pointer.

## Acceptance Criteria
- [ ] Running `run_liquidity_sweep_baseline.sh` produces `runs/<timestamp>/baseline_results.csv`
  and `runs/<timestamp>/report.html` (no flat-directory output).
- [ ] `bundle.json` exists in the run directory with correct `files` mapping.
- [ ] `qw record --bundle runs/<timestamp>` ingests the CSV and records the HTML blob
  without manual intervention.
- [ ] `qw record --bundle` receipt includes the `run_id` generated post-parse.
- [ ] Old flat-directory output from prior runs is not affected (backward compatibility
  for `qw record --file` remains unchanged).

## Validation
- Unit test: `bundle.json` reader returns expected file mappings.
- Unit test: `qw record --bundle` on a directory without `bundle.json` returns a clear
  error (not a silent skip).
- Manual end-to-end: run baseline, check directory structure, run `qw record --bundle`,
  confirm Run + BlobArtifact nodes in Neo4j.

## Open Questions
- Should `bundle.json` be a required pre-condition for `qw record --bundle`, or should the
  CLI fall back to auto-detecting files by extension/name pattern?
- Should the `runs/` directory live inside the trial directory
  (`research/trials/futures/liquidity_sweep/runs/`) or at a higher level
  (`research/results/runs/`)? A higher-level location makes it easier to query across trial
  families but breaks the current per-trial locality.
- Should `report_html` blobs be recorded to Neo4j or just tracked in `bundle.json` only?
  Neo4j node for a file path has low value if there is no graph query that uses it.

## Notes
The "orphaned artifacts" framing in the brief is slightly ahead of the current state:
HTML files are not tracked by the graph at all yet — they are already orphaned by design,
not at risk. This story closes that gap by making HTML linkage explicit, but the primary
value is eliminating filename collisions and enabling per-run artifact co-location.
